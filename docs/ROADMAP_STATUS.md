> **Binary resolution stops holding the server, 12 September 2026 ([ROADMAP_NEXT.md](ROADMAP_NEXT.md) item 1.2).** Done, with tests — and a planned item withdrawn:
>
> - **The planned work was withdrawn because its premise was wrong.** Item 1.2 said a wedged provider CLI could take the interface down. It cannot: a CLI is spawned as a separate process with piped stdio, so it can hold a queue slot but never the event loop. Extracting the 2 400-line `RunWorker` across a process boundary — which would also have forced multi-process SQLite or a large IPC surface — would have been substantial risk bought with an assumption.
> - **Measured instead of assumed.** Artifact capture reads untracked files with `readFileSync`, which looked like the culprit; across 2 000 to 20 000 untracked files the worst event-loop pause was **16–44 ms**, because the `diff.length < DIFF_LIMIT` check stops the reads. That check is load-bearing and does not look it, so `tests/artifacts-blocking.test.js` now fails if it is removed.
> - **One real problem was found.** Resolving a provider binary is synchronous, so whatever it waits for, every open page and WebSocket waits for. Its `where` / `which` fallback was capped at **five seconds** and re-ran on every launch attempt, so a PATH entry on an unresponsive network share froze the whole server repeatedly.
> - **Fixed narrowly.** The cap is now 800 ms — close to what a working lookup actually costs — and a resolution is cached for 30 seconds, keyed by binary name and PATH. A provider that is simply not installed no longer pays the full cost on every attempt, and the short expiry means installing a CLI is still picked up without restarting.
> - **Not changed:** `resolveBinary()` stays synchronous. Making it async would force `workflows/dryRun.js` `plan()` async and ripple through its callers, which is not worth it for a bounded wait.
>
> Verification: `npm test` 658 / 0 (five new across `tests/binary-lookup.test.js` and `tests/artifacts-blocking.test.js`). Server-side change: restart the server. No UI change, so nothing to look at.

> **Agents stop walking through the desks, 12 September 2026 ([ROADMAP_NEXT.md](ROADMAP_NEXT.md) item 1.1).** Done, with tests:
>
> - **The bug, exactly.** A desk agent was sent to `layout.desks[i]` — the desk *anchor*. The desktop is 1.9 × 0.95 centred 0.35 **behind** that anchor, so the anchor is underneath the desk and the figure stood inside its own furniture. Every walk was also a straight line between two points: the only thing any agent avoided was a conference-room wall, because those door waypoints were written by hand.
> - **An agent now sits at its desk.** `deskSeat()` puts it in the chair, 0.75 in front of the anchor, and the seated pose the conference table already used now applies at desks too — an agent working at its desk is sitting at it.
> - **Walks go round things.** `office/obstacles.js` reads the computed layout as rectangles (desktops, room cores, placed furniture by its catalogued radius; a rug is walked over, and a chair is deliberately not solid because every chair is some agent's destination). `office/navmesh.js` marks the floor at 0.35 units per cell, runs A\*, then pulls the path straight — leaving the two to five legs `followRoute()` already accepted. The grid is rebuilt with the room, never per frame.
> - **It reaches every agent by construction**, not per agent: it hangs off the one per-frame loop and off `followRoute()`, which every walk already went through. Conference walks keep their own door routing; the grid handles the open floor.
> - **It never strands anyone.** A goal inside furniture is moved to the nearest clear spot; a route that cannot be found falls back to the old straight line, because an agent that never arrives is a worse failure than one that clips a desk.
> - **They go round each other too** (`office/steering.js`). A walking agent steps aside for anyone in its way — across its direction of travel, so the walk still makes progress, and never more than 0.24. Someone standing or sitting keeps its place and is walked around. Agents notice each other two units out rather than at arm's length, because at walking pace a late reaction reads as two people teleporting apart. Two agents meeting head-on **pass on the right**, always the same way, because mirroring is the one case that deadlocks.
> - **They look at whoever is speaking**, and at nothing else. A glance follows a colleague with a *recorded message*, in the same room, within range; the head turns at most about 69° and simply does not turn at all for something behind the agent. Silence means every head stays forward — gaze is never invented, and there is no idle "looking around".
> - **A nudge can never break the floor rules:** it is applied after the path position is recomputed, so it cannot accumulate, and it is refused outright if it would put a figure inside an obstacle.
>

## What is genuinely left

### Provider surface truthfulness update — 10 September 2026

`GET /api/observation/status` now reports sanitized assistant surfaces with detection, observability, fidelity, and live-session counts. The Connections UI renders this as a signal bridge. Antigravity IDE data is detected separately from Gemini CLI and labeled detection-only until a verified Antigravity CLI or SDK event stream is available. This closes the visibility gap for installed-but-unobservable products without overstating provider support.

These are the things software in this repository cannot close, grouped by the reason. Everything else that is Partial has its missing piece named in its own Notes column and is ordinary remaining work.

**1. Needs a provider account, quota or binary we do not have.**

- **A completed, authenticated Codex run.** The adapter, the `exec --json` parser, the app-server JSON-RPC client and the approval routing all exist and are tested against fakes; the real attempt ended at the account usage limit. Until a Codex account with quota runs one bounded task here, `launch` stays `experimental` and the R2/Phase 2 gate stays Partial.
- **Any verified Gemini behaviour beyond the command line.** `gemini` 0.59.0 is installed and its flags are verified from its own `--help`, but the CLI has no auth method configured and exits 41 on every invocation. Stream vocabulary, usage and model reporting stay `unknown`, and the observer parses `~/.gemini` defensively with `unverified: true` on every session.
- **Cursor managed runs.** Only the Cursor IDE launcher is installed; `cursor-agent` is not. The adapter refuses to build a command rather than launching the IDE, and observation is limited to read-only conversation summaries.
- **ACP and A2A clients.** Both need a tested implementation to negotiate against; `copilot --acp` exists but is unverified here.
- **Model-API, GitLab, hosted-CI, database, document-store, design-tool and notification connectors.** Each needs an account or hosted service. They are absent rather than stubbed, because a connector that is listed but cannot probe would be a false "connected".

**2. Requires a hosted multi-tenant service.**

- **Roles, per-user permissions, tenant isolation, SSO and group provisioning.** Shared mode is one static bearer token that grants everything; the audit log honestly records the actor as `token`, not a person. Real roles need an identity service and a tenancy boundary that a single-process local app does not have.
- **Remote and cloud workers, runner enrolment, expiring pairing and revoke.** `runs.host` is always `local`. The disconnection half of this is done (interrupted runs are marked `disconnected`, never `cancelled`), but the enrolment, scoping and revocation half needs a service.
- **Private, expiring client-review links, shareable result cards and hosted replay links.** Each has to be served outside the local trust boundary.
- **A private connector/template catalog and any marketplace.** Also needs moderation, abuse reporting and an incident process.
- **Live teammate presence, comments, mentions, watch/unwatch, digests and quiet hours.** All of these presuppose more than one identified person; there is one local user and no notification channel to digest.

**3. Needs a native desktop-shell decision.**

- **Desktop app, signed installers, release channels, application rollback, upgrade and uninstall tests.** The Tauri-versus-Electron spike has not been run, so nothing downstream of it (installer, signing, updater, webview performance budgets) exists. This is a decision to make, not code to write first.
- **OS credential-store integration (DPAPI / Keychain / libsecret).** No secret is stored today, so nothing is at risk — but a real credential store belongs with the desktop shell.

**4. Needs design partners, user interviews or usability sessions.**

- **The positioning hypothesis, pricing, editions and the packaging table.** No price, no edition gate and no licence check exists in the code, and choosing them requires willingness-to-pay research.
- **Usability sessions** ("can a new user identify provider, target, task state, required decision and final artifact unaided?") and **customer case studies**.
- **The design-partner shortlist** from §19. The roadmap's own resume instruction forbids sending outreach, so this cannot be closed from here.
- **Explore-tier delight items** (seasonal themes, pets, collectibles, spatial audio, VR/AR, cinematic rendering) — the roadmap says adopt them only on evidence of retention or paid demand.

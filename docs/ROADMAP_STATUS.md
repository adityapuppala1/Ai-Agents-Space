## What is genuinely left

These are the things software in this repository cannot close, grouped by the reason. Everything else that is Partial has its missing piece named in its own Notes column and is ordinary remaining work.

**1. Needs a provider account, quota or binary we do not have.**

- **A completed, authenticated Codex run.** The adapter, the `exec --json` parser, the app-server JSON-RPC client and the approval routing all exist and are tested against fakes; the real attempt ended at the account usage limit. Until a Codex account with quota runs one bounded task here, `launch` stays `experimental` and the R2/Phase 2 gate stays Partial.
- **Any verified Gemini behaviour beyond the command line.** `gemini` 0.59.0 is installed and its flags are verified from its own `--help`, but the CLI has no auth method configured and exits 41 on every invocation. Stream vocabulary, usage and model reporting stay `unknown`, and the observer parses `~/.gemini` defensively with `unverified: true` on every session.
- **Cursor managed runs.** Only the Cursor IDE launcher is installed; `cursor-agent` is not. The adapter refuses to build a command rather than launching the IDE, and observation is limited to read-only conversation summaries.
- **ACP and A2A clients.** Both need a tested implementation to negotiate against; `copilot --acp` exists but is unverified here.
- **Model-API, GitLab, hosted-CI, database, document-store, design-tool and notification connectors.** Each needs an account or hosted service. They are absent rather than stubbed, because a connector that is listed but cannot probe would be a false "connected".

**2. Requires a hosted multi-tenant service.**

- **Roles, per-user permissions, tenant isolation, SSO and group provisioning.** Shared mode is one static bearer token that grants everything; the audit log honestly records the actor as `token`, not a person. Real roles need an identity service and a tenancy boundary that a single-process local app does not have.
- **Remote and cloud workers, runner enrolment, expiring pairing and revoke.** `runs.host` is always `local`. The disconnection half of this is done (interrupted runs are marked `disconnected`, never `cancelled`), but the enrolment, scoping and revocation half needs a service.
- **Private, expiring client-review links, shareable result cards and hosted replay links.** Each has to be served outside the local trust boundary.
- **A private connector/template catalog and any marketplace.** Also needs moderation, abuse reporting and an incident process.
- **Live teammate presence, comments, mentions, watch/unwatch, digests and quiet hours.** All of these presuppose more than one identified person; there is one local user and no notification channel to digest.

**3. Needs a native desktop-shell decision.**

- **Desktop app, signed installers, release channels, application rollback, upgrade and uninstall tests.** The Tauri-versus-Electron spike has not been run, so nothing downstream of it (installer, signing, updater, webview performance budgets) exists. This is a decision to make, not code to write first.
- **OS credential-store integration (DPAPI / Keychain / libsecret).** No secret is stored today, so nothing is at risk — but a real credential store belongs with the desktop shell.

**4. Needs design partners, user interviews or usability sessions.**

- **The positioning hypothesis, pricing, editions and the packaging table.** No price, no edition gate and no licence check exists in the code, and choosing them requires willingness-to-pay research.
- **Usability sessions** ("can a new user identify provider, target, task state, required decision and final artifact unaided?") and **customer case studies**.
- **The design-partner shortlist** from §19. The roadmap's own resume instruction forbids sending outreach, so this cannot be closed from here.
- **Explore-tier delight items** (seasonal themes, pets, collectibles, spatial audio, VR/AR, cinematic rendering) — the roadmap says adopt them only on evidence of retention or paid demand.

**5. Marketing or process activity rather than software.**

- The product site, use-case pages, launch videos, community showcases, a public changelog, public issue intake and a support channel.
- Certification badges for extensions: a review process and a publisher programme, not code. The registry already says out loud that a signature establishes the publisher and integrity, never safety.
- Independent security review for the R6 gate.

**6. Real work that is simply not done yet (no external blocker).**

Listed so it is not hidden among the blocked items:

- **Themes**: Data Lab, Research Library, Creative Studio and Campus, plus the theme builder. Design work inside `web/office/themes.js`.
- **Office scale**: instanced rendering and clustering of inactive agents; measured frame-rate budgets on a low-end laptop, mobile and this machine; the 10/50/100-agent scenarios. Until those are measured, no agent count or frame rate is promised.
- **Agent avatar and skill editing**: `agent_profiles.skills` and `agent_profiles.avatar` are stored, returned and rendered, but no API field or UI control writes them.
- **Office filtering**: the shared filter set narrows the Board, Timeline and Dependency Map but not the 3D scene.
- **A workflow scheduler**: `schedule` is a permitted trigger label with no timer behind it, so time zones, quiet hours, overlap policy and missed-run handling do not exist for workflows.
- **Dual approval**, a per-destination network allow list, and enforcement of `connections.allowedWorkspaces` — three policy fields that are recorded and displayed but not enforced.
- **A code-snippet artifact kind**, and applying or merging a reviewed worktree branch from inside the app.
- **Test gaps named in §18**: an out-of-order event contract test, one end-to-end scenario running two providers writing concurrently into two worktrees, a screen-reader pass and a contrast audit.

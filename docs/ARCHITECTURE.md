# Agent Space architecture brief (roadmap R2–R6 build)

This document is the working contract for everyone (people and agents) implementing PRODUCT_ROADMAP.md. Read it fully before touching code. It records what already exists, the shared vocabulary, verified provider facts, module ownership, and the acceptance rules.

## 0. Non-negotiable rules

1. **Truthful state.** Never present inferred activity as provider-reported. Every stored event carries `provenance` (`provider` | `inferred` | `user` | `system`). Activity labels derived from tool names are `inferred` and the UI must say so.
2. **No invented progress.** Observed and managed runs report elapsed time and milestones. Never fabricate percentages, conversations, or emotions.
3. **Never identify a provider from an open port or by scraping private application storage that the vendor does not document.** We read the vendor's own session files, registries, and headless JSON streams, and we launch the vendor's own CLI. Everything else is "unsupported" or "experimental" and labelled as such.
4. **Secrets never reach the database, logs, or the UI.** Use `isSecretPath()` from `contracts.js` before attaching or displaying files. Never store `auth.json`, `.credentials.json`, tokens, or `authToken` fields from lock files.
5. **Policies are enforced server-side**, not by hiding buttons. Unsupported capabilities are disabled AND rejected by the API with a clear message.
6. **Interrupting a run does not undo side effects.** Say so in the event and the UI.
7. **Node built-ins only.** The only runtime dependency is `ws`. Use `node:sqlite`, `node:child_process`, `node:fs`, `node:crypto`. Do not add npm packages. React, three, lucide-react are already present for the web app.
8. **Windows first.** Paths use backslashes; normalize with a shared helper (`normalizePath` in `packages/core/src/util/paths.js`, owned by the providers module, described below). Match cwd case-insensitively on win32. Spawn `.cmd` shims through `shell: true` only when needed; prefer resolving the real executable.
9. **Tests are mandatory per module.** `node --test tests/<file>.test.js` must pass. Use fixtures in `tests/fixtures/providers`. Never call a real provider CLI from tests; use the fake CLIs in `tests/fixtures/fake-cli/`.
10. **Formatting:** run `npx prettier --write` on files you touch. ESM only (`"type": "module"`).
11. **An address the caller chose is never connected to unchecked.** Outbound webhooks are the only place where a caller names a destination and the *server* opens the connection, which makes them the product's whole SSRF surface (`webhooks/target.js` — it is also the only outbound HTTP client in `core` and `server`, so keep it that way). Link-local is refused always, because that is where cloud metadata lives. Loopback and private addresses stay allowed when bound to loopback, since delivering to `localhost` is the ordinary use of a local-first tool, and are refused when bound to the network unless `AGENT_SPACE_WEBHOOK_ALLOW_PRIVATE` says otherwise. Validate the resolved address through a `lookup` passed to the request, not just the literal — a name is not judged until it resolves, and checking before connecting by name leaves a rebinding gap. If you add another outbound client, it goes through the same rule.

## 1. What exists today (R1–R6 build, after wave 2)

Verified on 10 September 2026: `npm test` 401/401, `npm run build` OK, `npx playwright test` 19/19, real server boot on Windows 11 with a live Claude Code session observed.

**Foundation**

- `packages/core/src/db.js` — `openDatabase(path)`, the migration list (v1–v6, v8, v9; **there is no v7** — the number was skipped when two wave-2 modules landed, so `schemaVersion(db)` reports 9), `transaction(db, fn)` savepoint helper, WAL + `busy_timeout` for file databases.
- `packages/core/src/contracts.js` — PROVIDERS, RUN_MODES, RUN_STATUSES, TERMINAL_RUN_STATUSES, ACTIVITIES, EVENT_KINDS, PROVENANCE, CAPABILITIES, AUTONOMY_PRESETS, DEFAULT_POLICY, `makeEvent()`, `classifyTool()`, `isSecretPath()`. **Use these.**
- `packages/core/src/TaskStore.js` — workspace-scoped tasks, `validateExtras` (target folder/files/range/documents, deliverable, provider, executionPolicy), `InputError(message, status)`.
- `packages/core/src/AgentProfiles.js`, `Workspace.js`, `WorkspaceHub.js` — editable profiles, per-workspace runtime, `snapshot()`, demo simulation confined to the demo workspace.
- `packages/core/src/services.js` — `createServices({db|dbPath, demo, port, env, observers, dataDir, …})`. Everything long-lived is composed **here, in dependency order** (see §4); nothing is started. `services.ready` resolves once optional modules have been scanned. `globalSnapshot()` builds the global-channel payload; `onClose(fn)` registers a shutdown step and runs it immediately if `close()` already ran.
- `packages/core/src/runs/RunRecorder.js` — the single write path for run activity: `ensureRun()`, `applyEvent()`, `setStatus()`, `update()`, `events()`, `addArtifact()`, `artifacts()`, `active()`, `find()`. Dedups by `providerEventId`, infers activity, mirrors run state onto the task, coalesces snapshot broadcasts.

**Execution**

- `runs/RunWorker.js` (~2 000 lines) — start → `assertDispatchAllowed` → `Policy.evaluateLaunch` → budget reservation → `RunQueue` → adapter → recorder → artifacts → review. Also `cancel`, `retry`, `input`, `reconcile`, `close`.
- `runs/queue.js` — round-robin fairness across workspaces, per-provider circuit breakers (opened only by `transport`/`provider-error`), rate-limit parking with `parseResetTime()`.
- `runs/budget.js` — `BudgetTracker`: estimate reservations in `budget_reservations`, post-hoc enforcement from provider-reported usage, `headroom()` that reports `reported: false` when nothing was reported.
- `runs/retry.js` — `classifyFailure()` (`transport`, `rate-limit`, `auth`, `usage-limit`, `provider-error`, `user-cancelled`, `side-effects-possible`, `unknown`) and `retryPolicy()` (bounded, jittered, never retries a run that may have written).
- `runs/outputScope.js` — `resolveRunScope()` → `worktree` (Git) | `output-folder` (non-Git documents) | `in-place`; `pinRange()`/`rangeIsStale()` pin a code range to a revision at launch.
- `runs/{worktree,artifacts,process}.js`, `adapters/{base,claudeCode,codex,codexAppServer,copilot,cursor,gemini,index}.js`.

**Policy, approvals, audit, ops**

- `policy/Policy.js`, `approvals/ApprovalService.js` (payload-hash binding, expiry sweep, urgency, `request-change`), `hooks/{claudeHookBridge,installer}.js`.
- `audit/Audit.js` — tamper-evident hash chain, `AUDIT_CHAIN_VERSION` 2 over canonical JSON including `workspaceId`/`runId`, with `legacyAuditHash()` so pre-upgrade rows verify as `legacy` instead of "tampered".

**Orchestration, context, analytics**

- `workflows/{TaskGraph,WorkflowService,contracts,checkpoints,dryRun,suggest}.js` and 13 template packs.
- `context/{ContextManifest,memory,relevance}.js`, `collab/{Handover,Decisions}.js`.
- `analytics/{Analytics,pricing,lineage,evaluation}.js`, `search/Search.js`, `export/manifest.js`.
- `connectors/{index,filesystem,git,github}.js` (read/write registry) and the optional `connectors/Connectors.js` (availability probes).
- `webhooks/WebhookService.js` (endpoints, signing, delivery and backoff) and `webhooks/target.js` (what an outbound delivery may connect to — see rule 11), `extensions/{manifest,registry}.js`, `mcp/{server,tools,resources}.js`.

**Server and web**

- `packages/server/src/server.js` — HTTP + WebSocket. Route modules in `routes/*.js` receive `ctx = { req, res, method, path, url, query, send(status, data), body(), services, hub, db, bus, actor }` and return `true` when handled; register in `routes/index.js` (order matters — see the header comment there). ## 2. Schema (migrations v1–v9 in `db.js`; `schemaVersion()` returns 9)

**v1 — identity.** `workspaces`, `agent_profiles`, `connections`, `tasks`, `runs`, `events`, `artifacts`, `approvals`.

**v2 — execution.**

- `workspaces`: + `auto_created`, `policy` (JSON, see DEFAULT_POLICY), `theme` (`studio` | `operations`), `settings` (JSON).
- `agent_profiles`: + `provider`, `auto_created`, `connection_id`, `skills` (JSON array), `avatar` (JSON string: `outfit`, `accessory`, `hairColor`, `pronouns`).
- `tasks`: + `depends_on`, `deliverable`, `target` (JSON `{folder, files[], documents[], range:{file,start,end,revision}}`), `provider`, `execution_policy`, `template_id`, `workflow_id`, `context`, `updated_at`, `review` (JSON `{runId, status:'pending'|'accepted'|'rejected'|'request-change'|'skipped', note}`).
- `runs`: + `mode`, `provider_session_id`, `cwd`, `branch`, `worktree`, `host`, `label`, `title`, `current_action`, `current_file`, `activity`, `last_event_at`, `usage`, `cost`, `exit_code`, `error`, `pid`, `source_path`, `source_offset`, `summary`, `orchestration_owner`, `attempt`, `parent_run_id`, `config_snapshot`, `context`, `prompt`. Unique `(provider, provider_session_id)`.
- `events`: + `provenance`, `data` (JSON, truncated to 4 KB), `tool`, `file`, `provider_event_id` (unique), `task_id`.
- `connections`: + `status`, `version`, `binary_path`, `home_path`, `last_probe_at`, `last_event_at`, `error`, `enabled`, `observe`, `owner`, `allowed_workspaces`, `details`, `updated_at`. Unique `(provider, alias)`.
- `approvals`: + `workspace_id`, `task_id`, `kind`, `payload`, `reason`, `decision`, `decided_by`, `expires_at`, `provider`, `provider_ref`.
- `artifacts`: + `workspace_id`, `task_id`, `title`, `content`, `size`, `metadata`.
- New tables: `audit_log`, `settings`, `observed_sessions`, `workflows`.

**v3 — token budgets.** `budget_reservations(id, workspace_id, run_id, estimate_tokens, created_at, released_at)`. Reservations are _estimates_ booked before a run starts and released when the provider reports its totals; the daily rollup is a query over this table plus `runs.usage`, never a second copy.

**v4 — provider control center.** `connections`: + `kind` (`coding-runtime` | `model-api` | `local-model-server` | `external-agent-service` | `workflow-engine`), `error_category`, `auth_expires_at`, `last_success_at`. New `connection_probes(id, connection_id, probed_at, ok, category, detail)` — the newest 20 per connection.

**v5 — tamper-evident audit.** `audit_log`: + `prev_hash`, `hash`, `sequence` (unique). Rows written before this migration keep NULL hashes and are reported by `Audit.verify()` as `unchained`, never as verified.

**v6 — orchestration.** `workflows`: + `version`, `published_at`, `definition_hash`, `external_id`, `owner`. `tasks`: + `contract`, `branch_condition`, `repair_of`, `reviewer`, `idempotency_key`. New `workflow_versions`, `checkpoints`, `webhook_endpoints`, `webhook_deliveries`, `webhook_inbox` (indexed by `payload_hash` for replay detection).

**v7 — does not exist.** The number was skipped; nothing depends on it and nothing should be added under it.

**v8 — context, knowledge, collaboration.** `memories(scope user|workspace|run, scope_id, kind, key, value, expires_at)`, `knowledge_collections`, `knowledge_items` (soft delete plus `?purge=1` hard delete), `context_transfers` (which provider/host received which permitted inputs — paths only, never contents), `handover_briefs` (`thread_id` groups versions; `generated` keeps the baseline beside the edited body), `decision_history`.

**v9 — analytics and evaluation.** `analytics_saved_views`, `scheduled_reports` (disabled by default; writes a local file only), `benchmarks`, `benchmark_cases` (inputs frozen as content hashes, never copied), `benchmark_runs`, `evaluations` (`dimension`, `verdict`, `score`, `grader`, `rubric`, `evidence`).

Every wave-2 migration is written so it does **not** depend on any other wave-2 migration having run: each only touches v1/v2 tables plus its own new ones, so the interleaved order in the array is irrelevant. Add further columns only by appending a new entry (v10+); never edit a shipped one.

- **Verified launch line** (`adapters/gemini.js`): `gemini -p "<prompt>" -o stream-json --approval-mode plan|auto_edit|yolo [-m <model>] [--include-directories a,b] [--session-id <uuid>] [-r <id|latest>]`. The approval mode comes from the autonomy preset (`propose`→`plan`, `scoped`→`auto_edit`, `sandbox`→`yolo`). `--skip-trust` is **never** passed automatically: skipping the folder-trust prompt is the user's security decision.
- **Auth-error envelope (real, captured here).** On failure the CLI prints a JSON envelope on **stderr**: `{"session_id":"…","error":{"type","message","code"}}`. `parseErrorEnvelope()` recognises it; `code === 41` (or a message matching "set an Auth method") is classified `not-logged-in`, and the run fails with the CLI's own wording, reused verbatim as `GEMINI_AUTH_FIX` in `providers/detect.js`: _"Please set an Auth method in your ~/.gemini/settings.json or specify one of the following environment variables before running: GEMINI_API_KEY, GOOGLE_GENAI_USE_VERTEXAI, GOOGLE_GENAI_USE_GCA"_.
- **Auth detection.** The authoritative "an auth method was chosen" signal is the existence of `~/.gemini/settings.json` — the CLI creates it only after you pick one. Contents are never read. `GEMINI_API_KEY`, `GOOGLE_GENAI_USE_VERTEXAI` and `GOOGLE_GENAI_USE_GCA` in the environment count too (`registry.gemini.authEnv`). The older `oauth_creds.json` guess is **wrong** and is not used.
- **Storage layout (verified by inspection, formats not verified).** `~/.gemini/projects.json` maps a lower-cased absolute cwd to a short project alias; per-project data lives in `~/.gemini/history/<alias>/` and `~/.gemini/tmp/<alias>/` (chats and `logs.json`). `~/.gemini/antigravity/` is the Antigravity IDE — a different product, detected and reported as unsupported, never parsed.
- **Observer rules** (`observe/gemini.js`): the _layout_ is real, the _file formats_ are not, so every `*.json` under those folders is parsed defensively (array of messages, `{messages|history|turns}`, or a flat log array) and anything unreadable is skipped rather than guessed at. Every session and every event carries `unverified: true`; usage parsed from these files is labelled `reportedBy: "unverified"`, never provider-reported. Live-ness is inferred from file modification time and is labelled as inferred.

### Common launch notes

- Spawn with `windowsHide: true`, `stdio: ["ignore","pipe","pipe"]`, `cwd`, `env: {...process.env, ...providerHomeOverrides}`, and `detached: true` off win32 (own process group for `killTree`). On win32, npm `.cmd` shims are resolved to the Node script they wrap (`resolveCmdShim` in `runs/process.js`) and spawned as `node <script> …` with `shell: false`; cmd.exe has no escape for `"`, `%`, `!`, or line breaks, so a `.cmd`/`.bat` that cannot be resolved is only run through the shell when no argument contains them (otherwise the launch is refused). Resolve binaries with `where` (win32) / `which`, filter by PATHEXT (`where` also lists the extension-less POSIX shim), and cache.
- Kill process trees on win32 with `taskkill /pid <pid> /t /f`; elsewhere `process.kill(-pid)` or `kill(pid, "SIGTERM")` then `SIGKILL`.
- Read stdout with a line splitter that tolerates partial lines and non-JSON noise (Codex prints warnings to stderr; Copilot prints ephemeral events).
- Override binaries for tests via env `AGENT_SPACE_BIN_<PROVIDER>` (e.g. `AGENT_SPACE_BIN_CLAUDE_CODE="node tests/fixtures/fake-cli/claude.js"`); fake CLIs replay fixtures and honor `--cwd`/`-C`.
- Override homes for tests via `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `COPILOT_HOME`, `CURSOR_HOME`, `GEMINI_HOME`.

## 4. Module ownership

One row per module. Own your files; consume every other module through the interface named here, and guard cross-module use with optional chaining (`services.approvals?.request(...)`) — every service is optional to its consumers, so a container built without one still answers.

**Composition order** (`services.js`, each step may use the ones before it):

```
db, bus, hub → settings → audit → policy → connections → recorder → approvals →
hookBridge → observation → runWorker (+ adapters, budget, queue, retry) →
decisions → workflows (TaskGraph, WorkflowService, checkpoints, dryRun, suggest) →
memory, relevance → analytics, pricing, lineage, evaluation → context → handover →
webhooks → ops (incidents, backup, health, diagnostics, retention) →
connectorRegistry, extensions, mcp → search → optional modules (services.ready)
```

`services.mcp` is a **factory**, never started in-process: `bin/agent-space-mcp.js` runs as its own process and talks to the server over HTTP, so it can neither contend for the SQLite write lock nor write protocol frames onto the server's stdout. `OPTIONAL_MODULES` is the only place an optional module is named; today it holds one entry (`connectors` — the provider-availability probe registry, which is a different thing from `connectorRegistry`).

## 5. Normalized event pipeline

```
observer.readEvents / adapter.parse / hookBridge.handleHook
   → NormalizedEvent (contracts.makeEvent)
   → RunRecorder.applyEvent(runId, event)
        - dedup (provider_event_id)
        - infer activity (classifyTool / kind) → stored in data.activity, run.activity
        - update run.current_action / current_file / actual_model / usage / last_event_at
        - waiting_approval ↔ running transitions
        - coalesced snapshot broadcast (hub "change" + bus "global")
```

Run status transitions: `queued → running → (waiting_approval|blocked|stale)* → completed|failed|cancelled|disconnected`. Stale is set by ObservationService/RunWorker when `now - last_event_at > staleAfterMs`; any new event returns it to running. Ended observed sessions → `completed`.

## 6. UI vocabulary

- Provider badge text: `Claude Code`, `Codex`, `Copilot`, `Cursor`, `Gemini`, `Manual`, `Demo`.
- Activity labels: Planning, Coding, Researching, Testing, Debugging, Reviewing, Running command, Messaging, Delegating, Needs approval, Blocked, Error, Stale, Idle. ("Available" is reserved for provider presence, so an agent with no recorded work is Idle.)
- Provenance chips: `provider` (solid), `inferred` (dashed outline, tooltip "derived from tool name"), `user`, `system`, `profile` (dotted: the working style set on an agent's profile, which nothing reported). Where one source is the norm (a provider run's events, the Activity feed) it is stated once and only other sources carry a chip.
- A manual task (no provider run) reports no activity. The snapshot's `state` for it is the profile's `workingState`, with `activityProvenance: "profile"`; clients show **In progress (manual)**, place the figure at its own desk, and never file it under the room that working style suggests (`isManualWork()` in `web/office/presence.js`, which also recognises the `user` value older servers sent).
- Provider work — a task that names a provider, or one a managed or observed run has executed — is never shown as manual. Assigning it opens no placeholder run (`Workspace.#startRun`); a managed run that starts closes any placeholder it replaces (`closePlaceholders`); and with no run executing, its agent is `IDLE` with `activityProvenance: "system"`. The workspace list's `activeRuns` counts such a task only while a managed or observed run is live, and manual work in progress still counts as before. Task rows, task details and board cards choose the run a task reports with `runsByTask()` (`web/hooks/viewLogic.js`), where a provider run wins over a placeholder.
- Never show a model name we did not receive: display "model not reported".
- Provider presence (top bar, `web/hooks/providerStatus.js`): **Running** (a live session or active run), **Available** (CLI found and a sign-in file exists — never a verified run), **Installed** (CLI found, sign-in not confirmed), **Failed** (the version check failed), **Not checked**. Absent providers are shown only on Connections, as **Not detected**, which is a fact about the machine and never raises the outage banner (a failed check or a tripped breaker does). A missing sign-in file keeps a CLI at **Installed** with the reason, because some CLIs keep their sign-in in the system keychain. Each state is a word and a shape, not only a colour. Capability levels on Connections come from the provider registry and say so; a probe re-runs detection and never verifies a capability.
- Run errors: only a run-level error (a stream error, a failed turn) becomes a run's `error`; a failed tool call stays on its event. Observed sessions never appear in the Inbox, which lists only runs Agent Space can act on.
- Activity from a shell command: Testing only when a test runner is invoked in command position (`runsTests()` in `core/contracts.js`), never when a runner's name appears in an argument, a quoted pattern or a heredoc.
- Context a tool adds to a conversation (attachment lists, reminders, a continued session's summary) is shown as "Added by the tool", not as the person's prompt (`isInjectedPrompt()` in `web/hooks/viewLogic.js`).
- A number the server did not send reads "Not recorded", never a dash under a basis label such as "counted".
- A live session is Active, Quiet (its run went stale: the process is open but nothing is recorded) or Ended (`sessionState()` in `web/hooks/viewLogic.js`); process liveness alone is never shown as work.
- Single-key decisions (Inbox A/D/C) act only on the request that holds focus, identified by id, never on a default or a list position.
- The global channel is one WebSocket per tab (`web/hooks/useGlobal.js`, a `useSyncExternalStore` store); components read it with `useGlobal()` and refresh on change with `useGlobalChange()`.
- Custom modals that are not a native `<dialog>` use `useDialogFocus()`: focus stays inside and returns to the invoker on close.
- A workflow template is never instantiated with an input missing: templates expose `inputKeys` and `WorkflowService.instantiate()` refuses with the missing keys named. Sample inputs are hints, never submitted values.
- A dependency proposal is checked with `POST /api/workspaces/:id/validate` `{ taskId, dependsOn }` (the stored graph with that task's dependencies replaced; nothing is written). `GET` checks the stored graph.
- Anything the office shows from history has a window and says its age: the handoff card 30 minutes (`HANDOFF_WINDOW_MS`), the build wall 2 hours. Snapshot times are epoch milliseconds; never pass them to `Date.parse()`.
- The office camera is fitted to the room's projected outline inside the part of the canvas the overlays leave free (`roomExtents()` / `roomFrustum()` in `web/office/data.js`); phone and portrait-tablet canvases take the room's shape.
- Run controls (Cancel, Retry, Provide input, Resume) are offered only for runs Agent Space launched (`mode: managed`); each is disabled with its reason when the run's state rules it out. An observed session says to act where it runs.
- The workspace snapshot carries the latest 60 events; older ones are read with `GET /api/workspaces/:id/events?before=<sequence>`, whose `total` counts every event up to `newest` (read together), so a client adds only the live events newer than that.
- A launch uses the first usable connection, in registry order, that the workspace may use (`allowedWorkspaces`); with none allowed, the policy refusal names why. The task launcher does not offer an account limited to other workspaces.
- Dual approval: each approver gives a name in the Inbox, recorded behind the transport actor (`local-user:Alice`). In local mode names are recorded, never verified. The Inbox sends the payload hash, so an approval applies only to what was shown.
- Codex app-server requests are evaluated by the workspace policy before a person sees them, as Claude Code hooks are: a denial is answered without asking anyone; a request that goes to a person carries its rule. A policy "allow" still goes to a person, because Codex asked.
- Applying a reviewed worktree (`POST /api/runs/:id/worktree/apply`) copies the changes into the working tree as uncommitted edits, from a patch built in a temporary index. It never commits, pushes, switches branch or touches the index, and refuses (nothing written) unless the review was accepted, the reviewed diff was complete and still matches the worktree, none of its files has uncommitted changes, and it is not already applied.
- Scheduling is the `scheduler.enabled` setting plus each schedule's own switch; `POST /api/scheduler/enabled` starts or stops the timer at once, and `POST /api/schedules/preview` answers "when would this run" without writing.
- Provider-backed tasks show the run's status and elapsed time, never a percentage (`cardProgress()` in `web/hooks/viewLogic.js`); only manual and demo tasks carry a percentage.
- Team relays (`POST /api/workspaces/:id/teams`, `core/workflows/WorkflowService.deploy`).
  - When a step is accepted, `TaskGraph.onTaskCompleted` hands its final message and artifacts to the next step. The message is fenced in the prompt (`handoffNote()`), or withheld when `context/untrusted.js` flags it.
  - Every such pass records a `handoff` event naming both agents, even when the next step did not start.
  - Accepting a review is what completes a managed step; the review gate is unchanged.
- Office moments (`web/office/episodes.js`, choreographed in `web/Office.jsx`).
  - A moment plays once, only for a record under 90 s old (20 s on first opening the office), and only between two different agents the roster knows.
  - It walks there, exchanges, walks back. Agents in a moment stay on the floor until it ends.
  - The caption says **Recorded**, **Simulated (demo)** or **Replay of a recorded event**, and opens the event.
  - Under reduced motion nobody walks or gestures; the caption still plays.
- Relay presence (`relayPresence()` in `web/office/relay.js`): a member whose step waits behind a colleague's _live_ step (active or blocked) stands at its desk labelled "Waiting for …"; a stalled relay puts nobody on the floor.
- Subagent helpers come only from the snapshot's `agents[].subagents` (open delegations).
- Desks are stable while agents come and go (`stableDeskOrder()` in `web/office/scale.js`).
- Pose angles: a positive shoulder angle swings the hand forward (figures face −z).
- Walking round the furniture (`web/office/obstacles.js`, `web/office/navmesh.js`). Both are pure arithmetic — no three.js, no agent, no run — so `node --test` covers them.
  - `officeObstacles(layout)` reads a computed layout as axis-aligned rectangles: one per desktop (1.9 × 0.95, centred 0.35 **behind** the desk anchor, which is why the anchor itself is inside the desk), one core per room that serves a function, and one per placed prop sized by its catalogued radius. A rug is walked over; a chair is deliberately not solid, because every chair is the destination of the agent whose desk it is.
  - `deskSeat(desk)` is where an agent belongs at a desk: the chair, 0.75 in front of the anchor. Sending a figure to the bare anchor put it inside its own desk.
  - `buildNavGrid()` marks the floor at ~0.35 units per cell, adding cost near obstacles so a path prefers the middle of an aisle. `findPath()` runs A\* and then pulls the result straight, dropping every waypoint whose neighbours already see each other; what remains is the two to five legs `followRoute()` in `avatars.js` already accepts.
  - The grid is rebuilt with the room, never per frame; a search runs once when a walk starts. Conference walks keep their own door routing (`routeBetween()`), and the grid handles everything on the open floor. **A path that cannot be found returns nothing and the walk goes straight** — an agent that never arrives would be a worse failure than one that clips a desk.
- Watching over a shoulder (`web/office/watch.js`, pure; driven by `camera.watch()`). The office camera is orthographic, so the vantage point sets the **angle** and closeness is zoom: the camera is placed a long way back along a fixed bearing so the near plane stays out of the room, and the zoom cap is raised while watching. The bearing is one part up to one part back, giving a polar angle near 1.07 rad — inside `OrbitControls`' own `[0.25, 1.22]` clamp, so the view never fights the control that owns the camera. The target sits in front of the agent at eye height, which is where its monitor is. Recomputed every frame from the figure's position and `renderYaw`, so it rides along; any orbit, reset or `setState` gives the camera back and restores the previous view. Watching and following are exclusive.
- Going round each other, and looking (`web/office/steering.js`, also pure). The grid plans against furniture once, when a walk starts; people are the part it cannot plan for, so they are handled per frame.
  - `separation()` returns a sideways offset for each **walking** agent. Someone standing or sitting keeps its place and is walked around — an agent at its desk has no reason to shuffle. The step is taken across the direction of travel, not backwards, so the walk still makes progress, and is capped at `MAX_NUDGE` (0.24).
  - Agents notice each other at `AWARENESS` (2 units) and reach full strength inside `PERSONAL_SPACE` (0.62). The gap between the two matters: two agents walking at each other close at twice the 2.3 units/second walking pace, so reacting only at personal space leaves about eight frames to move, which reads as teleporting apart. `tests/office-steering.test.js` simulates that approach frame by frame and asserts a real gap opens.
  - Dead ahead is the deadlock case — two agents mirroring each other never separate — so it is broken deterministically: **pass on the right**, the same way every time.
  - `Office.jsx` applies the offset after `animateFigure()`, which recomputes `fig.pos` from the planned route every frame while walking, so a nudge can never accumulate. It is refused outright if it would put the figure inside an obstacle.
  - `gazeTargets()` decides who each agent looks at, and **only a colleague the record says is speaking earns a glance** — a recorded message, never an inference. Nobody looks through a wall (`place` must match) or across the whole floor (`reach`). `gazeOffset()` caps the turn at `GAZE_LIMIT` (about 69°) and returns 0 for anything further round, so an agent never cranes at something behind it. Silence means every head stays forward.
- Conference rooms (`roomPlan()` in `web/office/scale.js`, `web/office/conference.js`, `web/office/conferenceScene.js`). These teams meet in a room in a wing on the floor's open (+x) side:
  - a live team relay;
  - each team of `ROOM_MIN` (4) or more, once more than `CLUSTER_THRESHOLD` (16) agents are on the floor;
  - any team the user invites.

  There are up to `MAX_ROOMS` (3) rooms, each with `ROOM_CAPACITY` (16) seats.
  - Nobody is hidden or drawn smaller. Seated agents are full figures, and every agent keeps its "Inspect" button.
  - Rooms stand in fixed slots (`MAX_SLOTS`), so a room never moves while another opens or closes. A room that leaves the plan waits `ROOM_GRACE_MS` before its members leave, and stays up until they have walked out.
  - Walks into, out of and between rooms follow door routes (`routeBetween()`), played as one eased walk (`followRoute()` in `avatars.js`).
  - The seated pose follows the recorded activity. Talking and passing work between agents play only for recorded messages and handoffs: across the table in one room, over the glass otherwise.
  - A relay member whose step just finished keeps its chair while its handoff plays (`holding`).
- Agents page portraits (`web/office/portraitStage.js`, rules in `web/office/portrait.js`). One WebGL renderer draws every card's figure, the office's own figure from `avatars.js`, and copies the frame into the card's 2D canvas: one WebGL context for the whole page. Only cards on screen are drawn. Without WebGL the cards fall back to 2D portraits.
- Managed runs record a subagent (a Task/Agent call) as a `delegation` event carrying its tool-use id, as observed sessions and hooks do (`toolEvents()` in `core/adapters/base.js`).
- Routing (`core/routing/router.js`) ranks assistants and never starts anything.
  - A cloud assistant's data destination is its vendor (`contracts.PROVIDERS[*].vendor`).
  - A task's label is the stricter of the workspace default and its own.
  - `Policy.evaluateLaunch` enforces `dataRules` and `providerDailyTokens` from the workspace policy only, never from a run override.
  - A fallback is offered only after `allowedFallback()` rechecks the data rule.
  - Pass rates rank only once `minEvaluations` results are graded.
- An arranged office (`core/visual/OfficeLayout.js`): `{ zones, props }`, where a zone is a shared room this workspace moved, renamed or gave another function (`does`), and a prop is a piece of furniture. A function belongs to one room: `zoneForActivity()` sends work to the room serving it, `buildZones()` builds that function's furniture and screens there, and work whose function no room serves happens at the agents' desks. Every coordinate is a fraction of the floor (-1 .. 1), so an arrangement survives the floor growing with the team, and the document carries no agent, task or path — which is what makes it portable inside a visual preset (version 2). The server validates it; `web/office/zones.js` places the rooms, `web/office/props.js` builds the furniture from the theme's materials, and `web/components/OfficeArranger.jsx` edits it in a plan view.
- Accessibility: one outline per page (h1 for the page, h2 for each section, nothing skipped), the sidebar and every region named, a polite live region per view, and the office announcing what only the picture shows (a team walking into a conference room, and the recorded moments). The 3D canvases are hidden from assistive technology: every fact above them is a named control and the roster repeats the floor in text. `e2e/screen-reader.spec.js` and `e2e/accessibility.spec.js` hold these.
- Stylesheets: `web/styles/tokens.css` is the only place tokens are defined; `web/main.jsx` imports tokens → components → base (`styles.css`) → experience → pages → shell, once, in that order. The scale is in rem and `:root` keeps the browser's own font size, so a reader who sets a larger default gets it; the interface's 14 px base sits on `body`. Nothing is set below `--text-xs` (0.75rem, 12 px at the usual default). Text colours come in token pairs (`--as-*`, `--act-*` for activity tones) checked at 4.5:1 or more in both themes; `e2e/accessibility.spec.js` measures rendered text on every view in both themes. Text drawn straight on an office backdrop uses `--office-ink`, which each backdrop sets.

## 7. Environment variables

`PORT`, `HOST`, `DEMO`, `AGENT_SPACE_DB`, `AGENT_SPACE_TOKEN`, `AGENT_SPACE_URL` (CLI/hook/MCP bridge), `AGENT_SPACE_OBSERVE` (`false` disables), `AGENT_SPACE_OBSERVE_INTERVAL` (ms), `AGENT_SPACE_DATA_DIR` (worktrees, output folders, artifacts; default `data/`), `AGENT_SPACE_BIN_<PROVIDER>` (binary override; provider id upper-cased with `-`→`_`), `AGENT_SPACE_BIN_GH` / `AGENT_SPACE_BIN_GIT` (connector binary overrides for tests), `AGENT_SPACE_HOOK_TIMEOUT` (hook CLI wait in seconds), `AGENT_SPACE_WEBHOOK_INTERVAL` (outbound drain, default 30 000 ms), `AGENT_SPACE_WEBHOOK_ALLOW_PRIVATE` (whether outbound webhooks may be delivered to loopback and private addresses; defaults to yes on a loopback-bound server and no on a remote-bound one — see `webhooks/target.js`), `AGENT_SPACE_HEALTH_INTERVAL` (health refresh, default 60 000 ms), `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `COPILOT_HOME`, `CURSOR_HOME`, `GEMINI_HOME`. A webhook endpoint's `secret_ref` also names an environment variable, which is the only place a shared secret is ever read from.

# Agent Space architecture brief (roadmap R2–R6 build)

This document is the working contract for everyone (people and agents) implementing PRODUCT_ROADMAP.md. Read it fully before touching code. It records what already exists, the shared vocabulary, verified provider facts, module ownership, and the acceptance rules.

## 0. Non-negotiable rules

1. **Truthful state.** Never present inferred activity as provider-reported. Every stored event carries `provenance` (`provider` | `inferred` | `user` | `system`). Activity labels derived from tool names are `inferred` and the UI must say so.
2. **No invented progress.** Observed and managed runs report elapsed time and milestones. Never fabricate percentages, conversations, or emotions.
3. **Never identify a provider from an open port or by scraping private application storage that the vendor does not document.** We read the vendor's own session files, registries, and headless JSON streams, and we launch the vendor's own CLI. Everything else is "unsupported" or "experimental" and labelled as such.
4. **Secrets never reach the database, logs, or the UI.** Use `isSecretPath()` from `contracts.js` before attaching or displaying files. Never store `auth.json`, `.credentials.json`, tokens, or `authToken` fields from lock files.
5. **Policies are enforced server-side**, not by hiding buttons. Unsupported capabilities are disabled AND rejected by the API with a clear message.
6. **Interrupting a run does not undo side effects.** Say so in the event and the UI.
7. **Node built-ins only.** The only runtime dependency is `ws`. Use `node:sqlite`, `node:child_process`, `node:fs`, `node:crypto`. Do not add npm packages. React, three, lucide-react are already present for the web app.
8. **Windows first.** Paths use backslashes; normalize with a shared helper (`normalizePath` in `packages/core/src/util/paths.js`, owned by the providers module, described below). Match cwd case-insensitively on win32. Spawn `.cmd` shims through `shell: true` only when needed; prefer resolving the real executable.
9. **Tests are mandatory per module.** `node --test tests/<file>.test.js` must pass. Use fixtures in `tests/fixtures/providers`. Never call a real provider CLI from tests; use the fake CLIs in `tests/fixtures/fake-cli/`.
10. **Formatting:** run `npx prettier --write` on files you touch. ESM only (`"type": "module"`).

## 1. What exists today (R1 complete)

- `packages/core/src/db.js` — `openDatabase(path)`, migrations (v1 identity, v2 execution). `transaction(db, fn)` savepoint helper.
- `packages/core/src/TaskStore.js` — workspace-scoped tasks, `InputError(message, status)`.
- `packages/core/src/AgentProfiles.js` — editable agent profiles, seeded defaults.
- `packages/core/src/Workspace.js` — runtime per workspace: `snapshot()`, `create/assign/update`, agent CRUD, demo simulation, `changed(message, kind, agentId, runId)` writes an event and emits `change`.
- `packages/core/src/WorkspaceHub.js` — all workspaces for one db, `get(id)`, `list()`, `create/update/archive/restore`, `snapshot(id)` (adds `workspaces` list), emits `change(workspaceId, snapshot)` and `workspaces`.
- `packages/core/src/services.js` — `createServices({db|dbPath, demo})` → `{ db, bus, hub, globalSnapshot(), close(), onClose(fn) }`. Modules attach themselves here (see §4 integration).
- `packages/core/src/contracts.js` — PROVIDERS, RUN_MODES, RUN_STATUSES, ACTIVITIES, EVENT_KINDS, PROVENANCE, CAPABILITIES, AUTONOMY_PRESETS, DEFAULT_POLICY, `makeEvent()`, `classifyTool()`, `isSecretPath()`. **Use these.**
- `packages/core/src/runs/RunRecorder.js` — the single write path for run activity: `ensureRun()`, `applyEvent(runId, normalizedEvent)`, `setStatus()`, `update()`, `events()`, `addArtifact()`, `artifacts()`, `active()`, `find({provider, providerSessionId})`. It dedups by `providerEventId`, infers activity, mirrors run state onto the task, and coalesces snapshot broadcasts. **Observers, adapters, and the hook bridge must go through it.** See `tests/run-recorder.test.js` for usage.
- `packages/server/src/server.js` — HTTP + WebSocket. Route modules in `packages/server/src/routes/*.js` receive `ctx = { req, res, method, path, url, query, send(status, data), body(), services, hub, db, bus, actor }` and return `true` when handled. Register in `routes/index.js`. WebSocket channels: `/ws?workspace=<id>` → `workspace:snapshot`; `/ws?channel=global` → `global:snapshot` (payload = `services.globalSnapshot()`; re-sent when `bus.emit("global")`). `bus.emit("workspace", id)` forces a workspace broadcast. Optional `AGENT_SPACE_TOKEN` enables bearer auth for shared mode.
- `packages/server/src/main.js` — entrypoint; env `PORT`, `HOST`, `DEMO`, `AGENT_SPACE_DB`.
- `apps/web/src/App.jsx` (~1350 lines), `Office.jsx` (Three.js), `useWorkspace.js` (workspace socket), `styles.css`.
- Tests: `tests/*.test.js` (node:test), `e2e/workspace.spec.js` (Playwright, Chrome, server on 5174 with in-memory db).

Snapshot shape today (`workspace.snapshot()`): `{ workspace, agents[], tasks[], runs[], events[], demoRunning, sequence, startedAt }` plus `workspaces[]` from the hub. Agents carry `state` (`workingState` while assigned, `BLOCKED`, or `IDLE`), `taskId`, `completed`.

### Common launch notes

- Spawn with `windowsHide: true`, `stdio: ["ignore","pipe","pipe"]`, `cwd`, `env: {...process.env, ...providerHomeOverrides}`, and `detached: true` off win32 (own process group for `killTree`). On win32, npm `.cmd` shims are resolved to the Node script they wrap (`resolveCmdShim` in `runs/process.js`) and spawned as `node <script> …` with `shell: false`; cmd.exe has no escape for `"`, `%`, `!`, or line breaks, so a `.cmd`/`.bat` that cannot be resolved is only run through the shell when no argument contains them (otherwise the launch is refused). Resolve binaries with `where` (win32) / `which`, filter by PATHEXT (`where` also lists the extension-less POSIX shim), and cache.
- Kill process trees on win32 with `taskkill /pid <pid> /t /f`; elsewhere `process.kill(-pid)` or `kill(pid, "SIGTERM")` then `SIGKILL`.
- Read stdout with a line splitter that tolerates partial lines and non-JSON noise (Codex prints warnings to stderr; Copilot prints ephemeral events).
- Override binaries for tests via env `AGENT_SPACE_BIN_<PROVIDER>` (e.g. `AGENT_SPACE_BIN_CLAUDE_CODE="node tests/fixtures/fake-cli/claude.js"`); fake CLIs replay fixtures and honor `--cwd`/`-C`.
- Override homes for tests via `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `COPILOT_HOME`, `CURSOR_HOME`, `GEMINI_HOME`.

## 5. Normalized event pipeline

```
observer.readEvents / adapter.parse / hookBridge.handleHook
   → NormalizedEvent (contracts.makeEvent)
   → RunRecorder.applyEvent(runId, event)
        - dedup (provider_event_id)
        - infer activity (classifyTool / kind) → stored in data.activity, run.activity
        - update run.current_action / current_file / actual_model / usage / last_event_at
        - waiting_approval ↔ running transitions
        - coalesced snapshot broadcast (hub "change" + bus "global")
```

Run status transitions: `queued → running → (waiting_approval|blocked|stale)* → completed|failed|cancelled|disconnected`. Stale is set by ObservationService/RunWorker when `now - last_event_at > staleAfterMs`; any new event returns it to running. Ended observed sessions → `completed`.

## 8. Acceptance (maps to roadmap gates)

- R1 (done): restart retains data; workspace isolation.
- R2: a task created in Agent Space runs through a provider adapter (fake CLI in tests; real Claude Code and Copilot verified manually), events drive the run, diff/tests inspectable, cancel/retry/input work, reconnect marks disconnected without duplicate execution, approvals flow through the inbox (hook bridge for Claude Code, app-server for Codex).
- R3: two providers concurrently with correct provenance and isolated outputs; unsupported actions disabled server-side.
- R4: recorded events drive office actions; themes switch without losing runs; reduced-motion and 2D board work.
- R5: dependency workflows with templates; usage/limits; analytics; replay.
- Shared mode: token auth, audit log, policy enforcement, tenant isolation by workspace.
- Every roadmap bullet gets a row in `docs/ROADMAP_STATUS.md` with Done / Partial / Deferred and evidence.

# Policy, approvals, audit, and shared mode

What the policy engine enforces, where it is enforced, how approvals are bound to what a person saw, what the audit log records, how shared-mode token auth works, and what is deliberately not enforced. Sources: `packages/core/src/policy/Policy.js`, `packages/core/src/contracts.js`, `packages/core/src/approvals/ApprovalService.js`, `packages/core/src/hooks/claudeHookBridge.js`, `packages/core/src/audit/Audit.js`, `packages/core/src/runs/RunWorker.js`, `packages/server/src/server.js`. Tests: `tests/policy.test.js`, `tests/approvals.test.js`, `tests/hooks.test.js`, `tests/run-worker.test.js`, `tests/server-security.test.js`.

## 1. Autonomy presets

Every workspace has one preset (`policy.autonomy`). The preset decides whether runs may be launched, what they may do, and whether "risky" actions can be routed to a person.

| Preset         | Label              | Launch | Write | Shell | Network | Isolation                  | Approvals | Effect on managed runs                                                                                                                                                                                                                      |
| -------------- | ------------------ | ------ | ----- | ----- | ------- | -------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `observe-only` | Observe only       | no     | no    | no    | no      | —                          | none      | Launches refused (403, rule `launch.observe-only`). Hook calls from sessions in this workspace get no decision (`passthrough`): Claude Code keeps its own permission prompts.                                                               |
| `propose`      | Propose            | yes    | no    | no    | no      | none                       | none      | Read-only runs: Claude Code `--permission-mode plan --allowedTools Read Glob Grep` (+ WebFetch/WebSearch only with `allowedNetwork`), Codex `-s read-only`, Copilot `--allow-tool view/grep/glob`. Hook: writes, shell, and network denied. |
| `sandbox`      | Execute in sandbox | yes    | yes   | yes   | no      | `worktree` (forced)        | risky     | Every run is forced into a Git worktree whatever the request or task asks (audited `run.isolation.forced`). Shell allowed inside it; risky commands ask; network denied unless `allowedNetwork: true`.                                      |
| `scoped`       | Scoped execution   | yes    | yes   | yes   | yes     | `none` (worktree optional) | risky     | Default. Writes to the project folder; the denied list wins, then risky commands and pushes ask for a decision.                                                                                                                             |

Presets are returned by `GET /api/policy/presets` and editable per workspace in Workspace settings → Execution policy.

## 2. Policy fields

Stored per workspace as JSON (`workspaces.policy`), merged over `DEFAULT_POLICY` on every read (`GET /api/workspaces/:id/policy`).

| Field                | Default                                                                                                                                        | Validation                | Used by                                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `autonomy`           | `scoped`                                                                                                                                       | one of the four presets   | launch verdict, hook/app-server decisions, adapter permission flags                                                                 |
| `maxConcurrentRuns`  | 2                                                                                                                                              | integer 1–10              | `RunWorker` queue per workspace                                                                                                     |
| `allowedFolders`     | `[]`                                                                                                                                           | ≤100 strings ≤500 chars   | file-scope checks, `--add-dir` grant, context manifest scope                                                                        |
| `deniedCommands`     | `git push`, `git push --force`, `rm -rf /`, `Remove-Item -Recurse -Force C:`, `npm publish`, `docker push`, `kubectl apply`, `terraform apply` | ≤200 strings              | command evaluation: an exact word-boundary match (quotes stripped) is always `deny`; entries ending in `:` or `\` match as prefixes |
| `requireApprovalFor` | `shell.risky`, `network`, `git.push`, `deploy`                                                                                                 | ≤20 strings               | which risky categories become `ask` instead of `allow`                                                                              |
| `budget`             | `{ maxTokensPerRun: null, maxRunsPerDay: null }`                                                                                               | null or positive integers | `maxRunsPerDay` refuses launches once reached; `maxTokensPerRun` is stored only (not enforced)                                      |
| `timeoutMs`          | 1 800 000 (30 min)                                                                                                                             | 60 000–7 200 000          | managed run kill timer                                                                                                              |
| `allowedNetwork`     | unset                                                                                                                                          | boolean                   | lets `sandbox`/`propose` runs use network tools; network requests become `ask` under `requireApprovalFor: network`                  |
| `autoDispatch`       | unset (true)                                                                                                                                   | boolean                   | `false` stops the task graph from launching ready dependents when a task completes                                                  |

A run-level override (task `executionPolicy` or the `policy` field of a launch request) can only tighten the workspace policy (`Policy.tighten`): a more restrictive preset, fewer concurrent runs, a shorter timeout, `allowedNetwork: false`, extra denied commands and approval categories. It can never widen it.

There is also a global `budget.dailyRunLimit` setting (`PUT /api/settings`) that counts managed runs across all workspaces.

## 3. Launch evaluation (`Policy.evaluateLaunch`)

Called by `RunWorker.start` and exposed as `POST /api/workspaces/:id/policy/launch`. Order:

1. `observe-only` → refused.
2. Workspace `budget.maxRunsPerDay` reached (managed runs started since local midnight) → refused (`launch.budget.workspace`).
3. Global `budget.dailyRunLimit` reached → refused (`launch.budget.global`).
4. Otherwise allowed with an `effective` block: `autonomy`, `isolation` (`worktree` forced for sandbox, else the request or the preset default), `allowedTools` (read-only set for propose), `sandbox` (`read-only` for propose, `workspace-write` otherwise), `network`, `maxConcurrentRuns`, `timeoutMs`.

`RunWorker` then applies the verdict: forced isolation is recorded in `config_snapshot.requestedIsolation` and a status event; extra directories (`task.target.folder` outside cwd) must be inside `rootPath` or `allowedFolders` or the launch is refused with 403; a refused launch is audited as `run.refused` with `policyDecision: deny`.

## 4. Tool-call evaluation (`Policy.evaluate`)

Called for every Claude Code `PreToolUse` hook (`claudeHookBridge.requestFromTool` maps Bash/PowerShell → `command`, Edit/Write/MultiEdit/NotebookEdit/Read → `file` with `access` write/read, WebFetch/WebSearch → `network`, everything else → `tool`) and by `POST /api/workspaces/:id/policy/preview`. When a `runId` is given, the run's `config_snapshot.autonomy` (the preset it was launched under) overrides the workspace preset, and the run's cwd, worktree, and granted extra directories count as scope.

Result: `{ decision: allow|deny|ask, rule, reason, autonomy, kind, category?, match?, path?, scopes? }`.

| Kind      | Order of checks                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| any       | `observe-only` → `allow` with `passthrough: true` (the hook answers `{}`, leaving the decision to the provider).                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `command` | 1. matches `deniedCommands` (quotes and backslashes stripped first, so `gi''t push` still matches) → `deny` (`command.denied`). 2. preset has no shell (`propose`) → `deny` (`shell.forbidden`). 3. risky pattern matched → `ask` when the preset allows approvals and the category (or `shell.risky`) is in `requireApprovalFor`; `deny` when the preset has no approval channel; otherwise `allow` (`…unlisted`). 4. else `allow`. Commands longer than 8192 characters are treated as risky (`too-long`) instead of being scanned. |
| `file`    | 1. no path → allow. 2. path looks like a secret (`.env*`, `*.pem`, `*.key`, `id_rsa*`, `.credentials.json`, `auth.json`, `secrets.*`, `.npmrc`, `.netrc`) → `deny` (`file.secret`). 3. write access and preset forbids writes → `deny`. 4. no scope configured at all (no rootPath, run cwd, allowed folders) → `allow` (`file.unscoped`, scope not enforced). 5. inside workspace root / run worktree / run cwd / allowed folder / run extra dir → `allow`; else `deny` (`file.out-of-scope`).                                       |
| `network` | preset forbids network and `allowedNetwork` is not true → `deny`; `requireApprovalFor` includes `network` and the preset allows approvals → `ask`; else `allow`.                                                                                                                                                                                                                                                                                                                                                                      |
| `tool`    | write-type tool name (`edit`, `write`, `create`, `apply_patch`, …) under a no-write preset → `deny`; else `allow`.                                                                                                                                                                                                                                                                                                                                                                                                                    |

### Risky command catalogue (`RISKY_COMMAND_PATTERNS`)

| Category      | Patterns (ids)                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shell.risky` | `rm-rf`, `rmdir-s`, `del-f`, `remove-item-recurse`, `git-reset-hard`, `git-clean`, `curl-sh`, `wget-sh`, `iex-download`, `sudo`, `chmod-777`, `format`, `mkfs`, `drop-table`, `truncate`, `ssh`, `scp` (scp/rsync), `env-dump` (`printenv`/`set`/`env` alone, `cat`/`type`/`Get-Content` of a `.env`), `indirect-exec` (`$(…)`, backticks, `eval`, `sh -c`, `xargs`, `iex`, `cmd /c`, `powershell -c/-enc`), `too-long` |
| `git.push`    | `git-push`, `git-force`                                                                                                                                                                                                                                                                                                                                                                                                 |
| `deploy`      | `npm-publish` (npm/pnpm/yarn), `docker-push`, `kubectl` (apply/delete/rollout/scale/patch/replace/drain/cordon/exec), `terraform-apply` (apply/destroy), `deploy-verb` (vercel/netlify/firebase/gcloud/aws/az/heroku/fly/wrangler/serverless/cdk/pulumi + deploy/publish/release/push/up)                                                                                                                               |

The catalogue is a heuristic: it is applied after whitespace normalization and quote stripping, but a determined agent can still phrase a dangerous command it does not recognise. The denied list is the hard stop; the presets and worktree isolation are the containment.

`POST …/policy/preview` (and the Preview box in the policy editor) returns the same verdict plus a plain-language `explanation`. It never bypasses enforcement.

## 5. Approval flow (`ApprovalService`)

1. **Request** (`request({ runId, kind, payload, reason, rule, provider, providerRef, expiresInMs })`): requires a run; the payload is secret-redacted (keys named token/secret/password/authorization/credential/… become `[redacted]`), hashed (`payloadHash`, SHA-256 over a stable JSON form), stored as `pending` with `expires_at` (default 15 min); an `approval.request` event (provenance `system`) puts the run into `waiting_approval`; the audit log records `approval.request` with `policyDecision: ask`; the global channel updates the inbox badge.
2. **Decide** (`POST /api/approvals/:id/decide {decision, note, payloadHash?}`): `approve`/`deny` only; 409 when already decided; 410 when expired (also marked on read); 409 when a supplied `payloadHash` differs from the stored one (the person decided on stale text). The row stores `decision`, `decided_by` (actor), `decided_at`, `_note`; an `approval.decision` event (provenance `user`) returns the run to `running`; audit `approval.decide` with the decision.
3. **Wait** (`wait(id, timeoutMs)`): the requester (hook bridge, Codex app-server adapter) blocks until decided, expired, or cancelled; when the caller's timeout passes first the approval is marked `expired` so the inbox never shows an undecidable item.
4. **Expiry sweep** every 30 s marks overdue rows `expired` (event + audit `approval.expire`). **Cancel** (`cancelForRun`) marks pending rows `cancelled` when the run ends (SessionEnd, cancel).
5. **Binding to what was shown**: for Claude Code commands the approval payload carries the whole command (`command`, up to 256 KB), a `commandPreview`, `commandSha256`, `commandLength`, and a `truncated` field list. If the approved payload does not carry the exact command (truncated or altered) the hook is denied and `hook.approvalMismatch` is audited. Codex app-server requests carry the command or the list of file changes and are answered with the protocol's decision enums (see [CONNECTIONS.md](CONNECTIONS.md) §3).

**Inbox** (`GET /api/inbox`): pending approvals, failed/stale/disconnected runs (retry from the inbox), tasks with `review.status === "pending"` (managed runs that finished and await accept/reject), and provider questions. Counts drive the rail badge.

**Timeouts that must agree**: Claude Code kills a hook after its configured `timeout` (installed as 300 s, `hooks.claudeCode.timeoutSeconds`), the hook CLI waits `--timeout` − 0.5 s, and the bridge waits `timeoutSeconds` × 1000 − 5 s before answering `deny` ("no decision in Agent Space within N s; approval expired"). Install with the same value everywhere (the installer and the route do this automatically).

## 6. Audit log (`Audit`)

Append-only `audit_log` rows: `{ id, timestamp, actor, action, target, workspaceId, runId, policyDecision, details }`. `details` is secret-redacted and capped at 16 KB. Read with `GET /api/audit?limit=&workspace=&run=&action=&since=` (newest first, ≤2000). Storage is plain SQLite (not tamper-evident).

Actions recorded today:

| Area      | Actions                                                                                                                                                                                                                                   |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Policy    | `policy.update`                                                                                                                                                                                                                           |
| Runs      | `run.refused`, `run.isolation.forced`, `run.queue`, `run.start`, `run.complete`, `run.failed`, `run.timeout`, `run.cancel`, `run.retry`, `run.input`, `run.disconnected`, `run.worktree.remove`, `run.review.accept`, `run.review.reject` |
| Approvals | `approval.request`, `approval.decide`, `approval.expire`, `approval.cancel`                                                                                                                                                               |
| Hooks     | `hook.deny`, `hook.approvalMismatch`, `hook.policyError`, `hook.invalid`, `hook.error`, `hook.badRequest`, `hooks.install`, `hooks.uninstall`, `workspace.autoCreate`                                                                     |
| Workflows | `task.dependencies.set`, `workflow.instantiate`, `workflow.archive`, `workflow.auto-dispatch`, `workflow.auto-dispatch.failed`                                                                                                            |
| Settings  | `settings.update`                                                                                                                                                                                                                         |
| Export    | `workspace.export`, `workspace.import`                                                                                                                                                                                                    |

Actors: `local-user`, `token` (shared mode), `hook:claude-code`, `system`. A note supplied with a decision is stored with the approval and echoed to the provider in the decision reason.

## 7. Shared mode and token auth (`server.js`)

- Default: bind `127.0.0.1`, no token, `Host` must be loopback, `Origin` (when present) must match the host. This is the local single-user mode.
- Setting `AGENT_SPACE_TOKEN` turns on shared mode: every `/api` request and every WebSocket upgrade must carry `Authorization: Bearer <token>` or `?token=<token>`; comparison is constant-time. The web app prompts for the token on 401 and stores it in the browser (`localStorage` key `agent-space-token`); the CLI takes `--token` or `AGENT_SPACE_TOKEN`.
- `HOST` other than loopback is refused at startup unless a token is set ("HOST is not loopback; set AGENT_SPACE_TOKEN"). With both set, non-loopback `Host` headers are accepted.
- Exception: `POST /api/hooks/claude-code` from a loopback TCP peer with a loopback `Host` is accepted without the token so the local Claude Code hook keeps working; that route can only record events and ask for approvals, never launch runs. The hook CLI fails closed (denies the tool call) on 401/403 for any other reason.
- Everything else about tenancy is single-user: one token grants full access to all workspaces, artifacts, settings, and hook installation. TLS is not built in; put a reverse proxy in front for remote use. Secrets never enter the database or the UI (settings refuse secret-looking keys; connection rows hold no credentials; events, approvals, and audit details are redacted).

## 8. What is enforced, and where

| Control                                                                         | Enforced by                                                           | Notes                                                                                                                                                           |
| ------------------------------------------------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Launch allowed / refused                                                        | `RunWorker.start` → `Policy.evaluateLaunch`                           | API 403 with the reason; the TaskLauncher only reflects it.                                                                                                     |
| Sandbox isolation                                                               | `RunWorker.start` (`enforcedIsolation`)                               | Worktree forced for `sandbox` regardless of request/task; retry/input go through `start` again.                                                                 |
| Read-only runs under `propose`                                                  | Adapter command lines (`permissionsFor`)                              | Claude `plan` mode + read-only tools, Codex `-s read-only`, Copilot read-only tool allow list, Cursor/Gemini omit `--force`/`--yolo`.                           |
| Extra folders (`--add-dir`)                                                     | `RunWorker.start`                                                     | Must be inside `rootPath` or `allowedFolders`; recorded in `config_snapshot.extraDirs` and counted as scope by the hook policy.                                 |
| Concurrency and daily run budgets                                               | `RunWorker` queue, `Policy.evaluateLaunch`                            |                                                                                                                                                                 |
| Run timeout                                                                     | `RunWorker.launch` timer                                              | Process tree killed; run `failed` ("timed out").                                                                                                                |
| Denied commands, risky commands, file scope, secret files, network, write tools | `Policy.evaluate` via the Claude Code hook bridge (PreToolUse)        | Only for Claude Code sessions with the hooks installed (interactive sessions, and managed runs when `--include-hook-events` applies to the same settings file). |
| Provider approval requests                                                      | Codex app-server adapter → `ApprovalService`                          | Only with `codex.useAppServer: true`.                                                                                                                           |
| Approval binding and expiry                                                     | `ApprovalService.decide/wait/expireSweep`, hook bridge command check  |                                                                                                                                                                 |
| Connection enabled                                                              | `RunWorker.providerAvailability`, `ObservationService.observeAllowed` | Disabled connections neither launch nor observe.                                                                                                                |
| Host/origin/token                                                               | `server.js`                                                           |                                                                                                                                                                 |
| Untrusted hook install commands/paths                                           | `routes/hooks.js` (`isTrustedCommand`, `allowedSettingsPath`)         |                                                                                                                                                                 |

## 9. What is not enforced

- **Copilot managed runs** run with `--allow-all-tools` (except under `propose`); Copilot's non-interactive mode has no per-call approval channel, so the denied list and risky heuristics do not apply to what Copilot executes.
- **Codex `exec` runs** (the default transport) have no approval channel either; containment is the `-s` sandbox flag and worktree isolation. The denied/risky rules apply to Codex only through the opt-in app server.
- **Observed sessions** of Codex, Copilot, Cursor, and Gemini are watched, never gated: Agent Space reads their files after the fact.
- **Claude Code without hooks** is observed only; with hooks, calls from a workspace set to `observe-only` (or when `hooks.claudeCode.passThroughAllow` hides allows) are left to Claude's own prompts.
- **File scope is not enforced when nothing defines a scope** (workspace without `rootPath`, no run cwd, no `allowedFolders`); the verdict says so (`file.unscoped`).
- **Network policy** is allow/ask/deny as a whole; there is no per-destination allow list.
- **`budget.maxTokensPerRun`** is validated and stored but never checked (providers report usage after the fact).
- **`connections.allowedWorkspaces`** is stored and editable but not checked at launch or observation time.
- **Risky-command detection is heuristic**: obfuscation beyond quoting (encoded payloads, scripts written to disk and then executed by an allowed command) is not recognised. Use `deniedCommands`, `propose`, or `sandbox` when that matters.
- **Side effects are never undone**: cancel, timeout, shutdown, and reconciliation stop or mark runs; every such event says "side effects already made are not undone".
- **No roles or per-user permissions**: in shared mode one token is full access; the audit log records `token` as the actor, not a person.
- **Retrieved content is not filtered**: instructions inside files, tool results, or web pages reach the provider through its own loop; Agent Space records events and cannot inspect what the provider read.

# HTTP API and WebSocket channels

Derived from `packages/server/src/server.js` and the route modules in `packages/server/src/routes/`. Routes are tried in the order listed in `routes/index.js`: connections, sessions, runs, approvals, policy, hooks, settings, audit, workflows, analytics, context, export, then the generic workspace routes.

## Conventions

- Base URL `http://127.0.0.1:5173` (`PORT`, `HOST`). All paths below are under `/api`.
- Requests with a body must send `Content-Type: application/json` (415 otherwise) and stay under 16 KB (413) unless a route says otherwise (hooks 256 KB, workflows 64 KB, context 256 KB, import 1 MB).
- Errors are `{ "error": "<message>" }` with 400 (validation), 401 (token missing/wrong), 403 (host/origin/policy), 404, 409 (state conflict), 410 (expired approval), 413, 415, 500, 503 (module not attached).
- The `Host` header must be loopback (`127.0.0.1`, `localhost`, `[::1]`) unless the server runs in shared mode; an `Origin` header, when present, must match the host. Responses carry `Cache-Control: no-store`.
- **Shared mode**: when `AGENT_SPACE_TOKEN` is set, every `/api` request and WebSocket upgrade needs `Authorization: Bearer <token>` or `?token=<token>` (compared in constant time). The only exception is `POST /api/hooks/claude-code` from a loopback socket with a loopback `Host`. Binding to a non-loopback `HOST` without a token refuses to start.
- `actor` recorded in audit rows is `local-user` (no token) or `token`.
- Timestamps are epoch milliseconds. Ids are UUIDs except workspace ids (slugs) and agent ids (8-char or workspace-prefixed).

## WebSocket channels (`server.js`)

| URL                  | Direction       | Messages                                                                                                                                                                                                                                                                                                                                                            |
| -------------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/ws?workspace=<id>` | server → client | `{ event: "workspace:snapshot", payload }` immediately on connect and on every change; payload is the workspace snapshot (see `GET …/workspace`) plus `workspaces[]`. Unknown workspace ids are rejected at upgrade.                                                                                                                                                |
| `/ws?channel=global` | server → client | `{ event: "global:snapshot", payload }` on connect and (coalesced, 50 ms) whenever connections, approvals, sessions, settings, or the workspace list change; payload `{ workspaces[], liveSessions[], connections[], inbox:{ counts, approvals[≤5], runs[≤5], reviews[≤5] }, settings (public subset), observation:{ enabled, running, lastPollAt, observers[] } }` |

Both channels are read-only (client frames are ignored), limited to 16 KB frames, pinged every 30 s (half-open clients are dropped), and need the bearer token (`?token=`) in shared mode. Same host/origin rules as HTTP. A client whose send buffer exceeds 1 MB is disconnected.

## CLI equivalents

`bin/agent-space.js` wraps the routes above: `workspaces`, `tasks [ws]`, `task create <ws> --title …`, `run <ws> <taskId>`, `runs [ws]`, `inbox`, `approve|deny <id>`, `doctor`, `sessions [--live]`, `templates`, `workflow start <ws> <templateId> --input k=v`, `graph <ws>`, `analytics`, `watch <ws>` (workspace WebSocket), `hook claude-code|install|uninstall|status`. Options `--url`/`AGENT_SPACE_URL`, `--token`/`AGENT_SPACE_TOKEN`, `--json`. Exit codes: 0 ok, 1 error, 2 usage.

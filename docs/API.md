# HTTP API and WebSocket channels

Every route served by `packages/server/src/server.js` and the modules in `packages/server/src/routes/`, regenerated after wave 2.

Handlers are tried in the order declared in `routes/index.js`:

```
ops → webhooks → search → connectors → collab → evaluation → extensions →
connections → sessions → runs → approvals → policy → hooks → settings →
audit → workflows → analytics → context → export → workspaces (must stay last)
```

`workspaces.js` owns the generic `/api/workspaces/:id/...` prefix and answers 404-by-fallthrough, so every module that claims a sub-path under it is registered first and returns `false` for anything that is not its own.

## Conventions

- Base URL `http://127.0.0.1:5173` (`PORT`, `HOST`). Every path below is under `/api`.
- Requests with a body must send `Content-Type: application/json` (415 otherwise) and stay under 16 KB (413) unless the route says otherwise: hooks 256 KB, workflows 64 KB, context 256 KB, workspace import 1 MB. The inbound webhook receiver reads the **raw** body itself, because the signature covers the exact bytes.
- Errors are `{ "error": "<message>" }` with 400 (validation), 401 (token missing or wrong), 403 (host, origin, or policy), 404, 409 (state conflict), 410 (expired approval), 413, 415, 500, 503 (module not attached).
- The `Host` header must be loopback (`127.0.0.1`, `localhost`, `[::1]`) unless the server runs in shared mode; an `Origin` header, when present, must match the host. Responses carry `Cache-Control: no-store`.
- **Shared mode**: when `AGENT_SPACE_TOKEN` is set, every `/api` request and every WebSocket upgrade needs `Authorization: Bearer <token>` or `?token=<token>` (compared in constant time). The single exception is `POST /api/hooks/claude-code` from a loopback socket with a loopback `Host`. Binding a non-loopback `HOST` without a token refuses to start.
- `actor` in audit rows is `local-user` (no token), `token` (shared mode), `hook:claude-code`, `mcp`, or `system`.
- Timestamps are epoch milliseconds. `since` parameters accept epoch milliseconds **or** an ISO date string. Ids are UUIDs except workspace ids (slugs) and agent ids (8-character or workspace-prefixed).
- Every route under `/api/ops` that changes operational state requires an explicit `{"confirm": true}` body field.

### Team records in the snapshot

- **`handoff` events.** One is recorded when a workflow step is accepted and the next step becomes ready, whether or not that next step could start. It carries `event.toAgentId` and `event.handoff`, which holds `{fromAgentId, toAgentId, fromTaskId, toTaskId, workflowId, dispatched, reason, withheld, simulated, artifacts:[{id, kind, title}]}`.
  - The next run's prompt gets the finished step's final message. It is fenced and labelled as another agent's output, not an instruction.
  - When that message reads like instructions, it is withheld (`withheld: true`), and the prompt says so instead.
  - `reason` says why the next step did not start, for example "no provider on task".
- **`team` events** carry `event.team = {workflowId, simulated, members:[{agentId, role}]}`.
- **`agents[].subagents`** lists an observed, managed or simulated run's open subagents, newest first, at most four: `[{id, description, startedAt, eventId}]`. A subagent is open when its delegation's tool-use id has had no `tool.end` or `error` yet. A "subagent finished" hook event carries no id and never counts as open.
- **Demo records** write `data.simulated: true`.

| Method | Path                    | Body / query                                                          | Notes                                                                                                                                                                                                                           |
| ------ | ----------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/routing`              | —                                                                     | `{levels, labels, vendors, providers:[{id, name, vendor, vendorId}], capabilities}`: the words routing uses                                                                                                                     |
| POST   | `/workspaces/:id/route` | `{taskId?, requires?:[capability], sensitivity?, allowExperimental?}` | Read-only ranking: `{label, candidates:[{provider, name, vendor, eligible, checks:[{check, ok, text, short}]}], recommended, why}`. Workspace policy fields (`PUT /workspaces/:id/policy`):

- `dataSensitivity`: `public | internal | confidential | restricted | null`.
- `dataRules`: `{label: [vendor] | null}`. A missing label, or `null`, means no rule; an empty list means no vendor may receive that label.
- `providerDailyTokens`: `{provider: tokens | null}`, counted from provider-reported usage today in the workspace.
- `routingPreference`: `[provider]`.
- `minEvaluations`: 1–1000, default 5.

A task's own label is `executionPolicy.sensitivity`. At launch the stricter of it and `dataSensitivity` applies, with the rules and caps read from the workspace policy. A refused launch reports `launch.data.destination` or `launch.budget.provider` and says why.

## WebSocket channels (`server.js`)

| URL                  | Direction       | Messages                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/ws?workspace=<id>` | server → client | `{event: "workspace:snapshot", payload}` immediately on connect and on every change. Payload is the workspace snapshot (the same shape as `GET /api/workspaces/:id/workspace`) plus `workspaces[]`. An unknown workspace id is rejected at upgrade                                                                                                                                                                                                                        |
| `/ws?channel=global` | server → client | `{event: "global:snapshot", payload}` on connect and, coalesced, whenever anything cross-workspace changes. Payload: `{workspaces[], liveSessions[], connections[], inbox{counts,urgency,approvals,runs,reviews}, providers{health,outages,breakersOpen}, operations{dispatchStopped,unacknowledgedStops,quarantinedHosts,revokedConnections,reason,stoppedAt}, health{status,alerts,alertCount,checkedAt}, settings, observation{enabled,running,lastPollAt,observers}}` |

The global payload is deliberately small — counts, levels and top-N lists. The full tables live behind `GET /api/ops/health`, `GET /api/inbox` and `GET /api/connections`. Each section is guarded, so one failing module degrades that section instead of taking the broadcast down; the health block is cached for 5 s because it stats the database file.

Both channels are read-only (client frames are ignored), limited to 16 KB frames, pinged every 30 s (half-open clients dropped), and need the bearer token (`?token=`) in shared mode. Same host and origin rules as HTTP. A client whose send buffer exceeds 1 MB is terminated rather than queued.

Server-side triggers: `bus.emit("global")` re-broadcasts the global snapshot; `bus.emit("workspace", id)` forces one workspace broadcast. `RunRecorder` coalesces both so a busy run does not flood clients.

## MCP surface (`core/mcp/*`, `bin/agent-space-mcp.js`)

A separate stdio process that speaks JSON-RPC 2.0 to an MCP client and plain HTTP to a **running** Agent Space. It never opens the SQLite file, so it cannot contend for the write lock and cannot see or change anything the HTTP API would not allow — server-side policy, approvals and audit apply unchanged.

```sh
node bin/agent-space-mcp.js [--url http://127.0.0.1:5173] [--token <t>]
```

Protocol revisions offered: `2025-06-18` (default), `2025-03-26`, `2024-11-05`. Frames are newline-delimited, ≤4 MB; stdout carries protocol frames only and every diagnostic goes to stderr.

## CLI equivalents (`bin/agent-space.js`)

`workspaces`, `tasks [ws]`, `task create <ws> --title …`, `run <ws> <taskId> [--provider …]`, `runs [ws]`, `inbox`, `approve|deny <id>`, `doctor`, `sessions [--live]`, `templates`, `workflow start <ws> <templateId> --input k=v`, `graph <ws>`, `analytics [ws] [--export csv]`, `watch`, `hook {install|status|uninstall|claude-code}`.

`--json` prints machine-readable output; exit codes are 0 (success), 1 (server unreachable or request failed) and 2 (usage error). `--token`/`AGENT_SPACE_TOKEN` and `--url`/`AGENT_SPACE_URL` apply to every command. `hook claude-code` is the command installed into Claude's `settings.json`: it fails **closed** (prints a `PreToolUse` deny) on any non-2xx response or timeout, and prints `{}` only when the server is not running, so an absent Agent Space never blocks Claude Code. It always exits 0.
